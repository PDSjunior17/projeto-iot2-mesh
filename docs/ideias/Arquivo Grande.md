- **Não é ACK**: ACK é aviso de recebimento, o que eu deveria ter colocado é o CRC-16 LoRa, que é implementado na camada física da rede lora, ou seja eu nem preciso calcular, és só chamar uma função na biblioteca do LoRa no nó que ele calcula e adiciona automáticamente
1. Através da interface do usuário, o dispositivo do usuário comprimi  a mensagem, criptografa  (utilizando a chave pública do destinatário) e a envia para a nuvem da AWS que vai estar rodando um nó IPFS, a nuvem vai pegar esse arquivo vai gerar um hash IPFS , vai pinnar o arquivo e vai retornar para o dispositivo do usuário o hash do arquivo;
2. A interface do usuário cria um aviso com o hash do arquivo para alertar a rede que o destinatário precisa acessar a internet e através do hash recuperar o arquivo que está na nuvem, o cabeçalho do aviso: id_origem/id_destino/flag_recebimento/hash_IPFS/ACK
3. A interface do usuário conecta via blueethoh a um nó da rede e informa que vai enviar um aviso e passa o mesmo
4. O nó envia o aviso em um tempo aleatório dentre um intervalo (para evitar que o aviso colida com outro se algum outro nó tiver usando o canal ao mesmo tempo) para os demais nó da rede em um canal específico (é sempre utilizado o mesmo canal para enviar avisos), cada nó que receber aquele aviso vai retrasmitir ele percebe que é um aviso de arquivo no IPFS então ele não troca de canal, o mantendo no canal de recebimento . O nó retransmite aquele aviso  um número M-1 de vezes(talvez adicionar um número que representa quantas vezes aquele aviso foi transmitido);
5. Depois de receber o aviso ele verifica usando o algoritmo de cálculo de erro e o número ACK(Acho que é CRC) para saber se ele sofreu interferência durante o envio, caso tenha sofrido o nó pede a rede que envie aquele aviso novamente;
6. Assim que receber o aviso e confirmar que ela está certo, o nó salva o aviso  em um arquivo único salvando-o no cartão de memória, ele verifica se o id_destino está conectado a ele no momento, se estiver ele envia o arquivo para ele, se não ele compartilha o arquivo baixado com os demais nós utilizando uma distância específica (os nós estaram espacialmente organizados sendo que terá três mais pertos, em que eles irão utilizar a distância longa de comunicação para comunicar  avisos e redundância de dados com nós distante e irão usar a distância curta para enviar mensagens entre eles criando uma redundância dos arquivos armazenados no cartão sd)
7. Quando um nó identificar que o id_destino está conectado a ele, o nó envia o arquivo para ele informando o destinatário e a mensagem e o dispositivo avisa se conseguiu receber a arquivo e descriptogrfar corretamente, caso tenha conseguido o nó envia um aviso para os demais nós da rede avisando que o aviso foi entregue ao destinatário, com o cabeçalho id_origem/id_destino/flag_recebimento(valor 1 indicando que foi recebido peo destinatário)/hash_IPFS/ACK
8. Os nós que receberem esse aviso irão adicionar 1 (que siginfica recebido) na tabela interna que está salva no cartão, tabela essa que associa cada mensagem a se  o destinatário daquela mensagem a recebeu ou não. Toda vez que um dispositivo se conecta a um nó ele verifica se tem alguma mensagem não recebida para aquele usuário, se tiver ele entrega e comunica a rede através do aviso de recebimento;
9.  Quando a rede estiver ociosa vai rodar a cada x minutos uma rotina para os nós compartilharem os seus arquivos entre si para gerar redundância na rede;
10. Se houver problema no recebimento em um bloco da  mensagem o nó solicita através de um aviso o reenvio do bloco que teve problema (assim que terminar o envio dos outros blocos)  usando o cabeçalho id_origem/id_destino/número do bloco/código_aleatório_uníco_da_mensagem/ACK. Primeiro o nó pede para os nós mais pertos via sinal mais perto a envio do bloco, se ele snã tiverem o nó pede para os nós mais distantes;
11. O dispositivo do usuário através da interface do usário que utiliza das bibliotecas, irá pegar o hash IPFS, vai baixar o arquivo, descriptografar ele e exibir no dispositvo do usário;
